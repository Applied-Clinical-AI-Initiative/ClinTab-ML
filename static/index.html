ClinTAB-ML

A clinical machine-learning workbench for tabular registry data. Upload a cohort, profile it, train and compare models, and get the diagnostics and reporting clinical prediction-model work actually requires.

Description

ClinTAB-ML takes a research team from a raw CSV (TQIP, NSQIP, or any tabular cohort) through column profiling, training and tuning across 15 algorithms, full diagnostic evaluation, restricted cubic splines, and the standard clinical-epidemiology calculators, all running on your own machine, so patient-derived data never has to leave it.

It exists because clinical researchers usually stitch an ML study together from disconnected tools: a notebook for profiling, hand-written scikit-learn code for models, an online calculator for odds ratios, a separate package for survival analysis. Each hand-off is a place where the statistical conventions clinical work depends on (leakage-free validation, calibration, corrections for zero cells) can quietly get skipped. This app builds those conventions in by default.

Process

1 Data Upload

Drop in a CSV and the app immediately profiles every column (binary, categorical, continuous, or date), flags anything with heavy missing data, and lets you decide column by column whether to keep, fill, or drop it. Optionally build your cohort with filters (procedure codes, age range and so on) and see how many patients each step removes. Set your train / validation / test split, random or stratified, and lock it in with one click.

2 Data Summary

Once the dataset is confirmed, every variable gets a full descriptive breakdown automatically: means, medians, spread, and missingness for continuous variables; category counts and percentages for everything else. No extra clicks, it's just there.

3 Model Training

Pick an outcome and the model list narrows to whichever of the 15 actually make sense for it: classifiers for binary or categorical outcomes, regressors for continuous ones. Hyperparameters get tuned against a genuinely held-out validation set (or k-fold CV, your call), and you watch it happen live instead of staring at a blank terminal.

4 Model Testing

Run any saved model against the test set or a brand-new file. ROC, precision-recall, confusion matrices, calibration plots, all rendered instantly, with multiple models overlaid on the same chart so comparing them is a glance, not a spreadsheet.

5 Spline

Not every predictor behaves linearly. Fit a restricted cubic spline against a continuous variable and see the actual shape of its relationship with the outcome, knots and confidence band included.

6 Clinical Epi

The calculators every clinical paper eventually needs: odds ratios and risk ratios from a 2×2 table, the minimum sample size for a prediction model, Kaplan-Meier survival curves, Cox regression, cumulative incidence with competing risks, Hosmer-Lemeshow calibration, the kind of thing that usually means switching between three different tools.

7 Reports

Everything you just did gets quietly logged in the background. This tab turns that log into a draft methods paragraph and checks it against the TRIPOD+AI reporting checklist, so you know what's already covered and what you still need to write up yourself.

T Leakage demo (teaching)

Train the same model the right way and in several common wrong ways on your own data, and see how much each mistake would flatter the AUROC you report compared with a lockbox of patients no version of the model ever touched. Built for workshops and journal clubs.

Column types & missing-data handling

Auto-detected: binary=2 values, categorical=strings or <10 integers, continuous=numeric >10 values. Any column with missing data gets a handling choice, defaulted by how much is missing: up to 50% is imputed (median for continuous columns, most frequent value for categorical), over 50% is removed. Fill values are learned from the training set only, after the split, and then applied to validation and test, so no information leaks from the held-out rows. Impute + missing indicator also adds a 0/1 column marking which values were missing. Fill 0 is never a default; use it only for counts where a blank means none. Override any column's choice as needed.

Sample size (before you build a model)

The minimum number of patients (and events) needed to develop a prediction model that will not overfit badly, using the four-step approach of Riley et al. (BMJ 2020). Work it out before you choose how many predictors to consider.

Cox proportional hazards

Text columns are always categorical. Tick a numeric code (such as ASA class 1 to 5) to compare each level with a reference instead of one hazard ratio per unit.

Competing risks (cumulative incidence)

When another event can stop the event of interest from ever happening (such as death before revision), 1 minus Kaplan-Meier treats those patients as if they could still have it later, so it overestimates the incidence. The cumulative incidence function counts competing events properly. Code the event column 0 for censored, the event of interest (usually 1), and any other code for a competing event (for example 2 for died before revision).
